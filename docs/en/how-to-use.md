# How to Use This Handbook

## Respect prerequisites

Each topic lists required prior topics. The registry enforces an acyclic dependency graph — you should not need a concept before it is introduced on your path.

## Page anatomy

Topic pages share one structure (see `standards/DOCUMENTATION_STANDARD.md`):

1. Why the concept exists
2. Mental model
3. Internal workflow / lifecycle
4. Browser, engine, React, Next.js, server, network, and memory perspectives
5. Performance, production examples, code
6. Common mistakes (≥10 when published), best practices, anti-patterns
7. Interview questions with answers
8. Official references

## Status meanings

| Status | Meaning |
| --- | --- |
| `stub` | Structure only — content not written yet |
| `outline` | Bullets / section notes |
| `draft` | Full prose in progress |
| `reviewed` | Peer-reviewed |
| `published` | Meets the quality bar |

Most pages begin as `stub` while the architecture is established.
